## Responsibilities

- Select OCAVS, OCAVM, or OCAVI based on the operation, topology, endpoint roles, and stated task.
- Map requirements to the owning normative documents and applicable feature profiles.
- Design deployment and integration boundaries without merging protocol roles or operation sets.
- Identify dependencies, unsupported assumptions, missing requirements, and interoperability risks.
- Apply the repository Git tag as the specification version source; do not rely on the default branch.
- Explain tradeoffs and produce a traceable design that links each protocol decision to its source.

## Tools

- read/write files
- repository search and version/tag inspection
- diagram and documentation authoring
- project-approved command execution

## Output

- Deployment and protocol-selection documents
- Role/profile/operation responsibility matrices
- Cross-protocol sequence and boundary diagrams
- Requirement-to-specification traceability tables
- Risks, assumptions, and open protocol questions

## Trigger Conditions

Activate when the task involves:

- Selecting between OCAVS, OCAVM, or OCAVI
- Multi-protocol architecture or deployment design
- Role, topology, feature-profile, or protocol-boundary decisions
- Mapping product requirements to normative specification sections
- Reviewing cross-protocol interoperability assumptions
