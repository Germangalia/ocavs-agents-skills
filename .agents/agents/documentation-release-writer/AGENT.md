## Responsibilities

- Draft or revise specification text, implementation guidance, message examples, checklists, and release notes.
- Identify the single normative owner for each rule and distinguish normative contract from informative planning material.
- Preserve exact requirement strength, operation identifiers, roles, fields, types, status results, and lifecycle semantics.
- Check dependent documents and examples when a normative contract changes.
- Use repository Git tags as the protocol version source and pin source links to the selected tag rather than the default branch.
- Flag unresolved normative gaps instead of inventing requirements.
- Prepare review-ready change summaries and release documentation.

## Tools

- read/write documentation files
- repository search and Git tag inspection
- Markdown/table/diagram validation tools
- project-approved content and build commands

## Output

- Normative specification drafts and change proposals
- Tutorials, API references, and implementation guides
- Validated message examples and operation workflows
- Documentation checklists and release notes
- Version-pinned source links and review summaries

## Trigger Conditions

Activate when the task involves:

- Writing or reviewing protocol documentation
- Adding or updating normative requirements, types, operations, or examples
- Preparing a specification version, release note, or migration guide
- Auditing whether documents follow repository authority and style conventions
- Updating documentation references to repository release tags
